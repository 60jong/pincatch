# catch pin 디자인 원칙

기준일 2026-11-05. 이 문서가 디자인 구현의 최우선 기준이다.

## 정체성

catch pin은 **듀오링고풍 플랫**이다. 단색 면, 아래쪽만 두꺼운 테두리, 통통한 버튼으로 손에 잡히는 느낌을 주되, 연출은 차분하고 고급스럽게 간다.

- **주인공은 핀과 보상**: 코발트 블루 핀과 골드 보상이 화면에서 가장 먼저 보여야 한다. 지도와 배경은 그보다 한 단계 조용하게 둔다.
- **진하게, 하지만 싸지 않게**: 색은 원색으로 진하게 쓰고, 광택·과한 그라데이션·만화적 장식은 뺀다.
- **글보다 그림**: 상황 설명 문구를 크게 띄우기보다 화면 자체(색 전환, 배지, 숫자)로 알려준다.

## 하지 말 것

| 하지 말 것 | 대신 |
| --- | --- |
| 애플/글래스 스타일(반투명 블러, 얇은 회색) | 단색 면 + 두꺼운 아래 테두리 |

| 싸구려 그라데이션, 광택 효과 | 단색 + 아래 그림자, 하이라이트는 작은 흰 사선 하나 |
| 대각선 줄무늬 배경 | 완전한 단색 또는 남색 방사형 그라데이션 |

| iOS 시스템 색(#FF3B30, #8E8E93, #007AFF 등) | 아래 색 토큰 |

## 형태와 컴포넌트

모든 눌리는 것은 아래쪽이 두껍고, 모든 담는 것은 둥글다.

| 요소 | 규칙 |
| --- | --- |
| 카드 | 테두리 2px, 아래 4px, 모서리 20px, 그림자 없음 |
| 주 버튼 | 높이 54, 모서리 16, `box-shadow: 0 4px 0 <진한 톤>`, 글자 900. 누르면 4px 내려감 |
| 보조 버튼 | 테두리만, 같은 높이·모서리 |
| 칩·배지 | 알약 모양(999px), 글자 12~13 / 900 |
| 토스트 | 탑바 아래 쌓임, 단색 + 아래 4px, 성공 5초 / 실패 2.2초, 탭하면 닫힘 |
| 바텀 시트 | 위 모서리 28, 손잡이 40×5, 뒷배경 어둡게 |

| 내 위치 | 프로필 사진 원 56px, 검정 4px 테두리 + 아래 4px 그림자 |
| 탭바 | 높이 88, 현재 탭은 파란 테두리 알약 안에 아이콘 |

## 글꼴과 문구

본문은 Gothic A1, 숫자·포인트는 Sora, 크게 외치는 결과 한 줄만 Black Han Sans를 쓴다.

- **굵기**: 제목·버튼 900, 본문 700, 보조 500. 듀오링고처럼 글자는 굵게.
- **크기**: 화면 제목 28, 카드 제목 15~17, 본문 15~16, 보조 12~13.
- **말투**: 해요체, 짧게. 숫자는 구체적으로(0.012초, +50P).
- **연출 문구는 최소로**: 결과 제목 한 줄("내가 먼저 잡았어요!", "아쉽게 졌어요")만 크게 쓴다.

## 모션 원칙

움직임은 빠르게 시작하고 부드럽게 멈춘다. 떨리거나 번쩍이지 않는다.

- **등장**: 누른 뒤 0.3초 안에 시작. 이징 `cubic-bezier(.22,1,.36,1)`.
- **기다리는 동안**: 흔들기 대신 후광이 1.6~1.8초 주기로 숨 쉬거나, 빛줄기가 1.1초마다 흐른다.
- **보상**: 숫자 카운트업(0.7초), 배지 통 튀어나기(살짝 넘치는 이징), 색종이는 이길 때만.
- **번쩍임**: 최대 불투명도 0.45, 화면 전환 순간에만.
- **구현**: 매 프레임 JS로 다시 그리지 않는다. Reanimated(웹은 CSS)로 transform·opacity·clip-path만 움직인다.
- **접근성**: '동작 줄이기' 설정이면 반복 애니메이션을 끈다.

## 판정 대결 연출

거의 동시에 눌렀을 때만 나오는 3초짜리 연출이다. 화면에 글은 없고, 폰 두 대·번개·타이머만 나온다. 기준 화면: `screens/source/JudgeWin*.dc.html`, `JudgeLose*.dc.html`.

1. **0~0.42초**: 남색 배경 좌우에 "나"와 "상대" 폰이 올라온다. 가운데 골드 VS 배지.
2. **0.6초**: 두 폰에 터치 원이 내려와 +50 핀을 누른다. 흰 물결 + 골드 방사선.
3. **0.6~0.92초**: VS가 작아지며 빠지고, 민트 번개(하나로 이어진 ⚡ 실루엣)가 위에서 아래로 0.3초에 그려진다.
4. **0.92~2.05초**: 후광이 숨 쉬고, 빛줄기가 번개를 타고 흐른다. 타이머 숫자가 돈다.
5. **2.05~2.56초**: 번개가 하얗게 차오른 뒤 사라지고, 이긴 쪽 화면이 퍼져 전체를 덮는다. 이김은 초록, 짐은 회색.
6. **2.48초~**: 결과. 배지 + 한 줄 제목 + 통계 카드 2장 + 버튼. 이길 때 색종이, "광고 보고 2배 받기".

결과 화면 아래에는 항상 "다음부턴 간단한 알림만 받기" 체크를 둔다. 생략하면 홈 토스트의 2배 받기와 2배 대기함(30분 보관)으로 이어진다.

## 지도 표현

지도는 실제 지도 타일이 아니라, 앱 카드와 같은 문법으로 직접 그리는 **배경 일러스트**다. 핀과 내 위치보다 항상 한 단계 연해야 한다.

- **블록**: 모서리 16의 둥근 타일. 연한 회색 바탕(#F8FAFD) 위에 아래로 4px 밀린 테두리색(#DFE5EF)을 깔아 카드처럼 보이게 한다.
- **도로**: 블록 사이의 빈 길(#EEF2F8). 큰길에만 흰 점선 차선.
- **공원·물**: 연초록(#DDF3E4)과 연파랑(#D6E7FF), 같은 방식의 아래 테두리. 나무는 두 겹 원.
- **라벨**: 흰 알약 칩, 화면당 3개 이하.
- **지형 6종**: 도심, 아파트 단지(동 번호 막대), 강변(다리·자전거길), 산(층층이 쌓인 등고선 면 + 점선 등산로), 바다(모래 띠 + 파도선), 논밭(줄무늬 밭 + 빨간 지붕). 기준 화면: `screens/source/Map*.dc.html`.

### 개발 팁 (Expo + TypeScript)

1. **그리는 도구**: `@shopify/react-native-skia`로 벡터를 직접 그린다. 지도 SDK(카카오·구글)는 이 모양을 낼 수 없다.
2. **데이터**: 서버에서 OSM(도로·landuse·water·park)을 내 주변 600m만 잘라, 단순화한 JSON으로 보낸다. 앱은 타일을 받지 않는다.
3. **좌표**: 위경도를 내 위치 기준 미터(ENU)로 바꿔 화면 중심(195, 412)에 둔다. 레이더 링과 같은 축척을 쓴다.
4. **블록 만들기**: 도로를 두께만큼 버퍼로 빼고 남은 땅 = 블록. 안쪽으로 6px 줄였다가 둥글게 다시 키우면(offset in → out, round join) 둥근 타일이 된다. `polygon-clipping`, `@turf/buffer`를 서버에서 돌리는 게 좋다.
5. **카드 느낌**: 모든 면을 두 번 그린다. 테두리색을 y+4로 먼저, 그 위에 채우는 색. 블러·그림자 필터는 쓰지 않는다.
6. **레이어 순서**: 도로 바탕 → 물 → 공원 → 블록 → 나무 → 차선 → 라벨 → 레이더 → 핀 → 내 위치 → UI.
7. **성능**: 지도는 `Picture`로 한 번 구워 캐시하고, 50m 이상 움직일 때만 다시 만든다. 레이더·핀 애니메이션은 별도 레이어에서 Reanimated shared value로만 움직인다. 매 프레임 React 리렌더 금지.
8. **테마**: 색을 코드에 박지 말고 `MapTheme` 토큰 객체 하나로. 라이트·다크·오프라인(회색) 세 벌을 같은 키로 둔다.
9. **지형 고르기**: 반경 안 landuse 비율로 결정(물 30% 이상 → 바다/강변, forest·peak → 산, farmland → 논밭, residential + 고층 → 아파트). 지형별 장식은 테마의 선택 레이어로.
10. **핀 배치**: 물·산 정상 등 못 가는 곳은 피하고, 핀끼리 72px 이상 띄운다.

```ts
type MapTheme = {
  road: string; tile: string; tileEdge: string;
  park: string; parkEdge: string; water: string; waterEdge: string;
  tree: string; treeEdge: string; label: string; dash: string; edgeOffset: 4;
};
type Terrain = 'city' | 'apartment' | 'river' | 'mountain' | 'sea' | 'farm';
```

## 다크 모드

모든 앱 화면은 라이트와 다크 쌍으로 만든다. 내 정보 → 화면 모드에서 시스템 / 라이트 / 다크를 고른다(기본값 시스템).

- **바탕 3단계**: 화면 #11141D → 카드 #1B2030 → 테두리 #2A3044. 아래 두꺼운 테두리는 그대로.
- **그대로 두는 색**: 코발트 버튼, 골드, 초록·빨강 토스트.
- **밝게 남겨야 하는 것**: 쿠폰 바코드(매장 스캔), 파란 카드 위 흰 버튼.
- **연한 색 배경**(연노랑·연분홍 배너)은 같은 색상의 어두운 톤으로, 그 위 글자는 밝은 톤(골드 #FFE08A 등)으로 바꾼다. 어두운 글자를 그대로 두지 않는다.
- **지도**: 남색 계열, 채도를 낮추고 차선·레이더 링은 아주 옅게.
- **판정 대결**: 라이트·다크 모두 같은 남색 배경. 결과 색만 한 톤 깊게.

## 구현 메모

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 화면이 버벅임 | 30ms마다 JS로 전체 리렌더 | Reanimated/CSS 애니메이션, transform·opacity만 |
| 그래픽이 안 보임 | SVG `url(#id)` 참조·SVG clipPath가 환경에 따라 깨짐 | 단순 도형 + 다각형 잘라내기 |
| 도형이 잘려 보임 | 면 분할·수평 계단, 다른 요소에 가려짐 | 한 덩어리 실루엣, 주변 UI와 간격 확보 |
| 스크롤 화면 카드가 찌그러짐 | 세로 flex 목록에서 자식이 줄어듦 | 자식에 `flex-shrink: 0` |
| 다크에서 글자가 안 보임 | 연한 배경만 바꾸고 진한 글자는 그대로 | 배경과 글자를 항상 쌍으로 바꾼다 |
